# 합성 공급자로 UTT 탐색·검색·상세·출처 흐름 구현

기존 인계에는 실행 서버·worker·인증이 없어 정적 화면과 순수 읽기 모듈만으로 사용자 흐름을 실행할 수 없었습니다. 기존 Python/ES modules 기술 구조에서 합성 전용 읽기 서버와 통합 UI를 구현해 프로젝트 탐색, 필터·정렬·페이지 검색, 상세·출처 좌표 확인, 사건 이력·관련 자료 이동과 결과 복귀를 연결합니다.

`DataProvider` 뒤로 접근을 분리하고, `ReadOnlyAdapter`는 설정 전 미연결을 반환합니다. 목록은 본문을 보내지 않으며, 커서는 조건·정렬·페이지 크기·snapshot에 묶입니다. 원문 강조는 해시·UTF-16 경계를 확인합니다. 합성 검토 연습은 탭 세션에만 남으며 원형 이력이나 정본 승인을 바꾸지 않습니다.

검증: Python 18개, Node 10개, 전체 Draft 2020-12 합성 요청/응답 검증 61회, 실제 Chromium 흐름 10개 묶음 통과. 생성 7,000건을 70페이지로 끝까지 조회해 중복·누락과 본문 전송 경계를 확인했습니다.

원본 계약·fixture·구 모듈·기존 테스트·참조 코드는 유지했습니다. 원본 매니페스트의 `.env.example`, `.gitignore`는 초기 입력에서 누락됐고 나머지 36개 해시가 일치했습니다. 새 `.gitignore`는 별도 작성한 개발 보조 파일입니다.

실제 연결·운영 승인·배포는 없으며 C 미리보기, D-1.1 원장 복원·정정, D-2 실제 영향 분석·일괄 제안은 미지원으로 명시했습니다. 원형 전체 복원·Windows·실제 데이터·실제 규모 검증은 주장하지 않습니다. 실행·검증 명령은 README, 남은 계약과 Work 측 시험은 docs/WORK_INTEGRATION.md에 있습니다.
